### 부분 실패·복구 계약 (요약)
- **단계**: `requested`(서버 결과 모름, 장벽 ON) → `pending`(서버 epoch 확정, 로컬 단계 남음, 장벽 ON — 복구 마무리/버리기만 허용) → 없음. `PurgeRecovery.resume()`이 어느 단계든 잇는다. 서버 purge는 재호출하지 않는다.
- **사진**: 행 파일 실패 → 행 유지(목록에서 재시도). 행 없는 파일 실패 → `photo_sweep_pending` + 개인정보 화면 "삭제하지 못한 사진 파일 N개 · 다시 시도" + 앱 시작/포그라운드 자동 재시도. 두 경우 모두 `PhotoWipeFailed(n)`(로그아웃·계정 삭제 중단) / `DeleteAllPartial(n)`(기록은 삭제됨).
- **세대 장벽**: 시작 시 세대 ≠ 잠금 뒤 세대 → 거부. 완료 뒤 새 액션은 통과. 단계 열림 + 일반 쓰기 → 거부(컨트롤러는 false/Failed, 측정 시작은 `startFailed` 문구).

### 요청 조정·오류 전파·재시도 계약 (요약)
- **단계**: `requested`(요청 id + 시각 저장, 장벽) → 응답 `served` → `pending` → 없음. 거절(4xx)은 즉시 해제. 유실(네트워크·타임아웃·5xx)은 프로필(`purge_request_id` 일치 또는 epoch 증가 = 처리됨)로만 확정; 같은 epoch·id 미기록은 요청 뒤 150초(Edge 실행 상한) 전엔 미확정, 뒤엔 "처리된 적 없음"으로 해제. 진행 중 호출이 이 프로세스에 있으면 어떤 복구도 판정하지 않고 기다린다.
- **재시도**: 복구(`resume`)는 서버를 다시 부르지 않는다. 사용자의 명시적 재시도만 같은 id를 다시 보내고 서버가 replay 한다.
- **사진**: 열지 못함/열거 실패 = 실패(표식 유지, 개수 모름). 개별 파일 실패 = 남은 파일 수. 둘 다 로그아웃·계정 삭제 중단, 전체 삭제는 부분. 다음 시작/포그라운드/화면 "다시 시도"가 재시도.
