## 다음 세션이 알아야 할 것

### S06 (측정 화면)
- 엔진은 `ref.read(seatEngineProvider)`. 사용 순서: `CameraPermission.request()` → `checkAvailability()` → `start(SeatEngineConfig(lowPower: …))`. 코드 예는 `docs/seat-engine.md` §7.
- **이벤트 의미**(decisions `[S04]`, S04c 갱신): `SeatCameraLost` · `SeatPaused` → `SessionTimeline.pause`, `SeatCameraRecovered` → `resume`. 백그라운드에서는 엔진이 스스로 멈추고 `SeatPaused` 를 내므로 `AppLifecycleState.resumed` 에서 `start()` 를 다시 부른다(실행 중이 아니면). Lost·Paused 동안 샘플은 오지 않는다.
- `SeatError(code)`: `permission_denied`(setupDen) · `camera_busy`(errCam → camBusyN 수동) · `no_camera`/`camera_init_failed`(수동 모드 제안) · `detector_failed`(측정 중단 시트 → 재연결/수동/종료).
- `lowPower` 사용 조건: 배터리 ≤ 20% 또는 설정. `battery_plus` 는 이미 의존성에 있다.
- 유지 창 3초는 엔진 내부. `AwayPolicy.thresholdFor(level)` 60·75·90초는 그대로 쓴다. 측정 결과가 들어오면 P2(고개 숙임) 검출률에 따라 임계 조정 제안을 이 문서에 추가한다 — 현재 제안 없음(실측 전).

### 안 한 일 · 미확인
- 실기기 측정은 그대로 이월(아래 APK). 검출기 무응답은 실기기에서 재현이 어려워 Fake 로만 고정 — 실측에서 "미완료 추론" 행이 0 이 아니면 CSV 와 함께 보고.
- 상한 상태(미완료 2)에서 매달린 호출이 영원히 안 돌아오면 앱 재시작 전까지 검출이 불가하다(의도: 네이티브 스레드 누수 상한). ML Kit 가 실제로 영구 무응답을 내는지는 미확인.
- `camera` 플러그인이 `CameraController` 를 2개 동시에 초기화하는 상황(늦은 open + 새 run)에서 플랫폼이 첫 컨트롤러의 초기화를 실패로 끝낼 수도 있다 — 그 경우 `_openBounded` 의 늦은 오류 경로(로그만)로 흡수된다.

### S06 인계 (S04d 추가분)
- `runStartedAt` 은 **`start()` 직전**에 `clock.now()` 로 1개만 잡는다(복귀 뒤 재시작마다 다시). 엔진의 `sinceStart` 0 은 `start()` 호출 순간이라 `runStartedAt + sinceStart` 가 그대로 맞는다 — 카메라가 느리게 열려도, 중단 뒤 복귀해도 샘플이 중단 구간 안으로 들어가지 않는다.
- `SeatError('detector_failed')` 는 이제 세 경우(예외 3연속 · 무응답 상한 · 상한 상태의 `start()`)에 온다. 중단 시트의 "재연결" 은 `stop()` → `startRun()` 이면 되고, 다시 `detector_failed` 가 오면 수동 모드 제안.
- `SeatCameraLost` 는 검출기 고갈로도 온다(카메라는 정상). 처리(`tl.pause`)는 같다.
- `stop()` 은 카메라 여는 중이면 즉시 돌아온다. 그 뒤 `start()` 를 바로 불러도 된다.
