## 다음 세션이 알아야 할 것

### 접근 규칙
- 기능 세션은 `package:soongong/data/repositories/repositories.dart` 의 `*RepositoryProvider` 만 사용. `AppDatabase` 직접 접근 금지. 부분 수정 인자는 drift `Value<T>`(`import 'package:drift/drift.dart' show Value;`).
- 사용자 데이터를 바꾸는 모든 메서드는 outbox 를 거친다. 서버 응답·pull 은 `applyServer*`/`applyStatus`/`applyLedger`/`applySdk` 만. 새 메서드를 추가할 때는 `SyncWriter.markUserWrite`(수정) 또는 `enqueue`(생성) 를 반드시 호출하고, 서버 컬럼은 `applyServerColumns` 로만 쓴다.
- 읽기 스트림은 기본적으로 `deleted_at IS NULL AND pending_delete_until IS NULL`.
- 시간: 저장소에 넘기는 `DateTime` 은 어떤 시간대든 되며 저장 시 `toUtc()`. 엔티티의 `DateTime` 은 UTC → 화면에서 `toLocal()`. 날짜 키는 `LocalDate`.

### S13 (동기화) 접점
- push payload = 데이터모델 §1.1 push 컬럼(내용 컬럼 + `created_at·client_updated_at·deleted_at·device_id·purge_epoch`); 행 헤더에 `id·base_server_version·purge_epoch`·outbox `mutation_id`. 로컬 전용 컬럼(`client_rev·base_server_version·pending_delete_until·confirmed_marks_json`)과 서버 컬럼은 `data` 에 넣지 않는다. tombstone 행은 `{deleted_at}`(reading_requests 는 D16 삭제 전용 mutation).
- 전송 전 `sync_outbox.sent_client_rev = 행.client_rev`, 승인 후 같으면 행 삭제, 다르면(전송 중 편집) 새 mutation_id 로 유지(enqueue 가 이미 `mutation_id` 재발급 + `sent_client_rev = null` 처리).
- 결정적 id: `activity_days`(user|date)·`settings`(user|key) 는 `core/domain/ids.dart` 의 uuid v5. 서버도 같은 네임스페이스. 거부(`version_conflict`)는 LWW 후 `applyServer`(서버 사본) 또는 재push.
- pull: 테이블별 `applyServer*(rows)`, `ledger` 는 `SubscriptionRepository.applyLedger`·`QuotaRepository.applyLedger`. `ApplyServerReport.dirtyOverwritten` 이 비어 있지 않으면 `sync_conflicts` 기록은 S13 몫. `sync_meta` 커서 키: `cursor_next_seq·last_synced_at·purge_epoch`.
- epoch 불일치·계정 전환: `AppDatabase.wipeAll()` + 사진 파일 삭제.
